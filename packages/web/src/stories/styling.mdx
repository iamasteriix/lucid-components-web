# Styles
<br/>


### Variants
This is the essence of the UI kit. A component's variants allow you to choose from a set of curated options, while keeping everything nice and clean by assembling the predetermined style combinations together using the `variant` prop. Each feature maps to your design tokens so everything stays consistent.

Use the `SxStyles.variants()` API for simplified development and readability. The method uses component names as top-level properties to provide type safety for the respective component's variants.

```tsx
import { SxStyles } from "@lucid-ui/web";

const variants = SxStyles.variants({
  view: {
    veneer: {
      name: 'glass',
      tone: 'neutral',
      intensity: 'base',
      elevation: 'level-1',
      blur: 'sm',
    },
  },
});
```

It helps to start with the `name` so you can get type suggestions for the rest of the `variant` props and their values.
<br/>


### The `sx` prop

Lucid Moonsong provides a deliberately limited `sx` prop for defining custom styles that have access to your theme. The constraint is meant to guide and enhance the design system's minimalist approach, which in turn means that you need to make thoughtful decisions about the story your interfaces tell and its impact on the experiences of your audience.

`SxStyles.create()` provides a simplified interface to define and manage your component styles, along with static type checking and suggestions.

```tsx
import { SxStyles } from "@lucid-ui/web";

const styles = SxStyles.create(
  card: {
    width: 'auto',
    height: 'space-16',
    borderRadius: '2xl',
  },
);
```
<br/>


### Vanilla CSS
Every component includes a `style` prop that accepts any valid CSS values. However, it exists solely for one-off overrides that fall outside of the component's semantic props or `sx`'s typed surface. Use it sparingly, and only when the design system cannot express the visual you need.
